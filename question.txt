هذا واحد من أجمل وأذكى الأسئلة اللي ممكن يسألها طالب آي تي، لأنه بيضرب في صميم فهم هندسة النظم (System Architecture)!

عشان تفهم الصورة الكبيرة وكيف مهاراتك اللي بتعرفها في SQL و Oracle APEX بتتقاطع مع اللي عملناه اليوم في بايثون، خلينا نقسم الجواب لجزئين

1. ليش ما استخدمنا Oracle APEX؟
Oracle APEX أداة عظيمة جداً (Low-code) وبتسرع الشغل، بس فيها ميزة بتعتبر عيب في بعض المشاريع الحديثة إنها مربوطة ببعضها (Tightly Coupled).
في APEX، قاعدة البيانات، والـ Back-end، وواجهات الـ Front-end كلهم كتلة واحدة داخل بيئة أوراكل.

بينما النهج اللي اشتغلناه اليوم (FastAPI) بيعتمد على بناء RESTful API مستقل تماماً (Decoupled).
شو الفائدة؟ الفائدة إنك بتقدر تبني الباك إيند مرة واحدة، وبعدين تربط عليه أي واجهة بدك إياها

ممكن تربط عليه تطبيق موبايل (Flutter أو React Native).

ممكن تربط عليه موقع ويب (React أو HTMLCSSJS).

ممكن حتى تربطه بتطبيق ديسكتوب (زي C# Windows Forms اللي إنت بتعرفه).
هذي الحرية ما بتقدر تاخذها بسهولة في APEX، عشان هيك الشركات بتفضل تبني APIs مستقلة.

2. ليش ما كتبنا أوامر SQL بإيدنا واستخدمنا Oracle Database؟
إنت كشخص قوي بالـ SQL، ممكن تستغرب ليش كتبنا كود بايثون بدل ما نكتب INSERT INTO أو SELECT  FROM.
السبب هو استخدامنا لتقنية الـ ORM (Object-Relational Mapping) اللي هي مكتبة SQLAlchemy.

ليش SQLite مش Oracle؟ إحنا استخدمنا SQLite لأنها أسرع للتطوير والتعلم (ما بتحتاج تنصيب سيرفر ضخم وتجهيز يوزرات). بس المفاجأة الحلوة بفضل الـ ORM، إنت بتقدر تحول مشروعك هذا ليشتغل على Oracle Database بثواني! كل اللي عليك تعمله هو إنك تغير سطر واحد فقط في الكود (سطر الـ SQLALCHEMY_DATABASE_URL) وتخليه يأشر على سيرفر أوراكل، والـ ORM رح يترجم كل كود البايثون لأوامر SQL بتفهمها أوراكل تلقائياً بدون ما تعدل حرف بالـ CRUD!

ليش ORM مش Raw SQL؟ كتابة الـ SQL جوا الكود بتزيد احتمالية الأخطاء والثغرات الأمنية (زي الـ SQL Injection). الـ ORM بيحميك من هاي الثغرات، وبيخلي الكود أنظف وأسهل للصيانة.

الخلاصة
إنت ما استغنيت عن علمك بالـ SQL؛ الـ ORM هو فعلياً بيكتب SQL بالنيابة عنك وراء الكواليس. والمهارات اللي تعلمتها في قواعد البيانات (زي العلاقات، الـ Primary Keys، والـ Foreign Keys في الجداول الضعيفة) هي بالضبط اللي خلتك تفهم كيف تصمم جداول المسلسلات والحلقات اليوم وتستوعبها بسرعة.

هسه بما إن الـ API صار مستقل وقوي، إحنا جاهزين تماماً ننتقل لمتعة الـ Front-end ونبني واجهات تتصل بهذا السيرفر وتجيب منه البيانات.

حابب نبلش نبني صفحة ويب بسيطة (HTMLJS) تتصل بالـ API تبعنا وتعرض المسلسلات، ولا بتفضل نستخدم تقنية معينة ببالك؟
